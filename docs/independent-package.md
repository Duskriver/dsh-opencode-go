# Independent package decision

The plugin owns its Host adapter, Web settings entry, build, package manifest, activation layer, and tests. It consumes DSH through published npm exports. The source tree and build have no reference to a DSH checkout.

The Host depends on DSH services through peer dependencies so Cordis service classes and LLM error identities remain shared with the application; the two DSH utility packages the Host imports, `@deepseek-ai/dsh-brand` and `@deepseek-ai/schemastery`, are peers for the same reason. The Client resolves React, the store, and UI primitives through the DSH module table. UI type packages are optional peers because headless installations do not mount those services; this project's development dependencies supply the types and test runtime libraries.

The package's bundle keeps the configuration entry `id: opencode-go` so existing settings remain attached. Its LLM provider route is independently named `dsh-opencode-go`, shown as `DSH OpenCode Go`, and can coexist with the generic adapter's `opencode-go` route. The SDK retains its native `opencode-go` identity for transport behavior; replay metadata records the DSH route and an optional `sdkProvider` to restore the native identity. The original fork's `llm-opencode-go` row can be disabled by a profile patch. Plugin registration does not select the user's default model or replace another provider automatically. Saved session/preset provider selections must be updated explicitly.

The plugin owns request-history, stream and replay conversion in `src/conversion.ts`, with the upstream MIT license. It consumes only published host APIs from DSH `0.2.1-rc.5` and later. Protocol transport remains implemented by the pinned private pi-ai SDK, with Google adapter wrappers in `src/google.ts` and the request-local fetch binding in `src/transport.ts`.

The build uses esbuild and lightningcss, with Rollup to flatten the exported SDK declarations. The host bundles the required pi-ai implementation and only the OpenCode Go model catalog. DSH services, Undici, OpenAI and Anthropic SDKs stay external; DSH class identities remain shared. The browser factory follows DSH's `window.__ModuleLoader__.load` format, embeds CSS Modules, and allows only the declared platform module imports. A package-level builder is sufficient for this single external plugin; extracting a general DSH build-tool package would require a separate release and is not a prerequisite for installation.

The minimum supported Host is DSH `0.2.1-rc.5`, with Cordis `^4.0.5`. `@deepseek-ai/dsh-brand` (`>=0.2.1-rc.5`) and `@deepseek-ai/schemastery` (`>=3.18.5 <4`) are peer dependencies supplied by the Host installation rather than dependencies installed by the plugin, so a profile keeps one copy of each even when the application ships a newer DSH release. Development dependencies and the lockfile pin the DSH `0.2.1-rc.5` release, Cordis `4.0.5` and Schemastery `3.18.5`. Consumer installation uses the prebuilt artifacts and does not run a plugin build. Releases are guarded: `prepack` re-runs `check:dist`, `prepublishOnly` runs the type checks plus the artifact/tests gate, and `check:pack` (also a CI step) asserts the tarball contents. `lib/build-info.json` records the package version, and the tarball ships `scripts/licenses/pi-1.5.0-LICENSE` with the third-party licenses so the notice reference resolves inside the package.

Verification uses 20 domain-focused Vitest files against published rc.5 APIs, separate host/client type checks, a byte-for-byte independent rebuild and Cordis's ordinary package resolver. The suite imports the current 25 implementation modules directly. `npm run verify:installed -- /path/to/consumer` exercises a consumer's resolved package; `npm run verify:headless -- /path/to/consumer` additionally exercises the official CLI with a temporary profile and loopback gateway. The default `verify` includes the complete test suite. See [development](development.md) and [verification](verification.md) for commands and scope.

The initial source derives from the user's working copy of DeepSeek Harness on branch `oh-my-dsh`, whose HEAD was `2c8555b323f3b49eac743bafd527f9f3238bf548`, including the uncommitted OpenCode Go settings changes present when this project was created. Runtime conversion modules retain their published behavior. The original checkout is unchanged by this extraction.
